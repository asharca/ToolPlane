# 统一入口与执行前审批

> [English](A2A_INGRESS_APPROVALS.md)

面向部署者、工作区管理员和集成开发者。本增量连接现有原生任务核心，**不代表全部运行时和真实端到端验收已经完成**。

## 支持边界

Pi、Claude Code、DSH、Hermes RPC 的经典聊天、Work、Agent Control MCP 和经过授权的消息渠道，均通过 `submitNativeEntry` / `runNativeEntry` 提交至同一个 A2ATask / A2AContext / Worker。启用条件不满足会拒绝执行，**不会回退旧执行器**。独立原生工作台和标准 A2A/MCP 服务入口继续使用同一核心。

托管 `hermes` 的经典运行及公共隔离服务仍保留其兼容执行方式。其原生会话审批无法可靠绑定单次工具调用的问题尚未解决，不能宣传所有运行时完全迁移。入站服务不因此获得私人 Agent 或浏览器审批权限。

本地 Agent 必须在 A2A 设置中显式启用、配置模型及独占联网 Docker 沙箱。升级不会自动启用任何 Agent。经典入口暂时仅接受文本，附件和旧运行时 slash 命令不会静默丢弃或绕过新审批执行。

## 原会话与原生任务映射

新增 `A2AEntryBinding` 绑定调用身份、入口种类、原会话/Work ID 与原生 Context；`A2AEntryReceipt` 保存消息 ID、内容摘要及已接受的 Task。映射、去重记录和任务准入在同一事务中写入。

首次从旧会话进入会创建新的原生 Context，旧历史仍可阅读，但**不会导入旧工具操作或自动复制完整记忆**。只把新的明确用户输入转成任务；后续消息复用原生 Context。旧 WorkSession / Conversation 作为界面记录保留，不再承担受支持原生运行时的执行调度。

同一消息 ID、同一内容重试返回已接受的任务；相同 ID 更换内容被拒绝。INPUT_REQUIRED 使用原 Task 和新消息 ID，不延长截止时间；终态后的新输入创建新 Task。不同调用用户不能借用另一用户的原生 Context。

HTTP 断开仅停止观察，已经接受的任务继续存在。经典聊天的停止读取动作不等于取消任务，应在链接的原生工作台明确取消。Work 的明确取消标志会传递到原生任务并约束后代；已发生的外部副作用不会回滚。失败 Work 的原消息不能被当作“新重试任务”静默重放，需要提交明确的新输入。

## 消息渠道的执行身份

外部聊天用户 ID 不是 ToolPlane 用户 ID。管理员必须在 **Agent 设置 → A2A 接入 → 消息渠道执行身份** 中将当前账户显式绑定为操作人，不能由模型或来信参数指定任意平台用户。绑定不扩大原消息渠道的联系人、来源和沙箱限制。

执行中持续检查操作人、连接状态、渠道配置及祖先授权。解绑或配置变化后，根任务、子任务和审批读取均不得继续沿用原权限。没有绑定时失败关闭，绝不推断使用工作区所有者。

渠道响应可给出原生工作台链接；该链接不授予权限，只有绑定的真实平台操作人登录后才能审批。外部消息中的“批准”不是控制面决策。任务持久化不等于渠道最终回复已持久投递：本增量没有增加渠道 outbox，进程中断后的最终消息投递仍需进一步验收。

## 执行前审批

新增 `A2AToolApproval` 绑定 Task、本轮执行租约、原生 call ID、工具名称、规范化参数摘要和失效时间。记录不接受来自模型的批准指令。

受支持的工具拦截器先注册，再通过短期运行凭据报告就绪。就绪前模型和 MCP 代理拒绝该轮访问。CLI 进程的复用签名包含短期凭据摘要，新轮次不会使用上一轮租约，但仍保留原生会话状态。

审批页面展示工具名称与原始 JSON 参数，并提供“仅批准此次”和“拒绝”。初版对本地原生工具采取保守逐次审批；批准不是永久 allowlist。参数最大 16 KiB，每任务最多 32 条，最多等待 5 分钟且不超过任务剩余期限。

批准与消费通过事务串行处理，一次批准最多消费一次。重复消费、参数变更、取消、过期、撤权和旧租约均不会执行。批准响应丢失时宁可拒绝，不自动重放可能已执行的操作。审批写入审计只记录标识、摘要和决定，不记录完整参数。

任务在一个仍存活的执行前回调等待时保持标准 WORKING，不新增 A2A 枚举，也不把普通工具审批伪装成 AUTH_REQUIRED。此阶段占用执行槽和沙箱；不是透明的进程检查点恢复。未决审批不能被执行器误报为任务完成。

## 运行时适配与已知限制

| 运行时 | 拦截方式 | 限制 |
| --- | --- | --- |
| Pi | `tool_call` 扩展在执行前阻止调用 | 需要锁定运行时契约；尚无真实模型端到端通过结果 |
| Claude Code | SessionStart / PreToolUse，明确设置文件，移除该模式的 blanket bypass | 保留 dontAsk；运行时自身异常/Hook 故障语义须真实 CLI 验证，不能据此宣称恶意 CLI 的强隔离 |
| DSH | `tools/pre-execute` 中间件，保留后续拒绝结果 | 不以工具活动日志代替拦截，需真实 CLI 验证 |
| Hermes RPC | 原始 `tool_execution` 中间件，批准后才调用一次 `next_call` | 内置交互 `approval.request` 尚不能安全绑定单次调用，保持拒绝，不关闭内置审批 |

审批控制面不作为操作系统沙箱边界。人批准任意 shell 后，命令本身能做的事情仍取决于沙箱与已有权限。不要给不受信任的运行时/插件额外管理凭据。

## 路由

```text
POST /api/v1/agent-runtime/a2a/{taskId}/approvals
GET  /api/v1/workspaces/{slug}/agents/{agentId}/a2a/console/approvals?rootTaskId=...&taskId=...
POST /api/v1/workspaces/{slug}/agents/{agentId}/a2a/console/approvals
```

运行时入口只接受该 Task/租约的签名运行凭据，可报告 ready 或 check，不能批准。浏览器入口只接受同源登录态，拒绝账户/服务 Bearer 回退、跨站 Origin、伪造用户和修改参数；决策必须绑定当前页面看到的 inputHash。经典入口通过接受提示中的工作台链接审批，尚不是每个旧界面都内嵌新审批面板。

## 迁移与验收

在本 PR 既有 A2A 核心、本地协作、存储计量、远程注册迁移之后依次应用：

```text
20260923110000_a2a_tool_approvals
20260923113000_a2a_entry_bindings
```

随后生成 Prisma Client 并按单运行时所有者流程重启。迁移默认不绑定历史 Work 或渠道操作人；历史记录不被自动启动或重放。不要在生产上运行本地测试/seed。

重点测试包含同请求去重、追问、配置/身份撤销、一次性审批、前置网络失败拒绝、HTTP 鉴权/CSRF 和 UI 决策。Hermes 合约测试运行未修改的上游中间件，但替换注册表及工具回调，**不是实际 Hermes CLI 或模型验收**。本地 PGlite 也不能代替真实 PostgreSQL 并发。

完整第三方 TCK、实际模型/远程 TLS、真实浏览器与全部入口 end-to-end 必须另有实测报告；预检或组件测试通过不能当作这些项目通过。参见 [验收前置条件](A2A_E2E_VALIDATION.md)。
