# 原生 A2A 工作台

> [English](A2A_WORKBENCH.md)

面向工作区日常使用者。工作页面顶部的 **A2A 工作台**，以及 **Agent 设置 → A2A 接入 → 打开工作台**
均可进入原生任务界面。直接地址：

```text
/app/{workspace}/work?mode=a2a&agent={agentId}
/app/{workspace}/work?mode=a2a&agent={agentId}&task={taskId}
```

该模式直接调用原生 A2A Handler、Task、Context 和 Worker，不生成兼容 Responses、私人 Conversation
或旧 WorkSession。URL 只包含选择信息，不携带凭据；打开链接、刷新、切换 Agent 都不会执行任务。
同一任务地址只有通过当前登录身份及工作区授权后才能读取，分享链接不会授予访问权限。

## 开始使用

先在 [A2A 接入设置](A2A_CONSOLE.zh-CN.md) 中配置模型、独占联网 Docker 沙箱并明确启用内部 A2A。
支持 Pi、Claude Code、DSH、Hermes RPC；托管 Hermes 继续使用已有公开服务和经典工作入口。
工作台只展示当前工作区受支持的普通 Agent，不会自动启用未授权的 Agent。

选择 Agent，输入任务目标并点击提交。任务被接受后页面保存其地址并展示协作树、状态、任务消息与交付物。
提交会消耗模型和工具资源；“已接受”不等于“已完成”。无需在浏览器粘贴账户或外部服务密钥。

左侧按当前调用身份加载最近 20 个任务，可逐页加载，界面最多保留 200 条列表项。选择历史任务只是查询，
不会重新执行。列表刷新失败与任务读取失败分别提示；初次任务查询失败可显式重试读取，不会自动提交新工作。
完整读取权限仍由原生核心检查，知道其他成员或委派子任务的 ID 不等于能独立打开它。

## Task 和 Context 的续写规则

| 当前状态 | 输入行为 |
|---|---|
| 未选择任务 | 新消息创建新 Task 和 Context |
| `INPUT_REQUIRED` | 新 messageId 补充原 taskId，保留原 contextId 与截止时间 |
| `COMPLETED`、`FAILED`、`CANCELED`、`REJECTED` | 新 Task 复用原 contextId，并通过 referenceTaskIds 引用上一任务；不重新打开终态任务 |
| `SUBMITTED`、`WORKING` | 等待任务结果或明确取消，不追加并发执行 |
| `AUTH_REQUIRED` | 不把普通消息当作授权，不提供“自动批准” |

“新建上下文”与“继续当前上下文”不同。前者开始新的原生会话；后者保留原 Context 的运行时会话关联。
独立 Context **不是新文件系统**：同一个 Agent 仍使用其已配置沙箱中的文件和原生记忆。
任务消息最多读取 32 条，任务树和交付物沿用核心上限，不把无限历史塞进页面或模型。

## 网络异常、重试与取消

每次提交先在当前页面内存保留 messageId 和完整请求内容。网络断开或结果无法确认时，不自动重发；
点击“重试同一条消息”才发送同一份请求，服务端利用原生消息去重返回既有任务。请求未确认时输入及任务选择锁定，
避免用户修改内容后误用相同 ID。此时仍可刷新任务列表检查接受情况。

可以明确丢弃本地待确认请求再开始新工作，但它**不会取消服务器上可能已接受的任务**。待确认内容不会写入
localStorage 或 sessionStorage，刷新或离开页面后无法保证恢复未确认消息的 ID；应先查询任务列表，不盲目重复提交。
已接受任务有带 taskId 的地址，刷新或重进页面仅恢复其状态。

离开页面会中止浏览器读取，不取消已接受任务。取消必须显式确认；界面显示取消请求后继续观察，直到核心确认停止
或返回真实终态。已经发生的工具副作用不会回滚，已提交的远端网络请求也无法强制撤回。

任务树采用只读自动轮询，不是模型逐 Token 流。页面隐藏时暂停，可手动暂停/刷新，网络错误采用有限重试。
收到 401/403/404 时清除已有任务快照并停止自动读取，不继续展示已失效权限的缓存；普通临时网络故障仍可保留最近
快照并显示错误。恢复访问后需要再次明确读取。

## 与经典 Work、聊天及消息渠道的关系

工作台是 `/work` 页面的**显式原生模式**，不是把旧记录换个名称。原 `w`、`c` 链接继续打开经典 Work/聊天，
与 `mode=a2a` 混用会被拒绝，防止把历史记录作为新任务执行。返回经典工作入口不会搬迁、删除或重放旧会话。

原生模式按明确启用的 Agent 能力范围执行，使用新的逐次工具审批，不借用旧 WorkApproval 记录。
受支持的经典入口已接[统一提交与审批](A2A_INGRESS_APPROVALS.zh-CN.md)；托管 Hermes、某些原生交互审批及旧历史记忆的完整迁移仍未完成。
本地/远程委派可由任务运行时使用既有受限工具发起；远端来源仍需部署白名单、管理员注册/启用与逐 Agent 授权。
参阅[远程 Agent](A2A_REMOTE_AGENTS.zh-CN.md)和[内部协作](A2A_LOCAL_COLLABORATION.zh-CN.md)。

## 验证与部署边界

本增量不改数据库 schema 或依赖；部署整个 PR 时仍需应用此前列出的原生、内部、计量和远程迁移。
前端组件测试和隔离数据库验证覆盖续写、追问、去重、恢复地址、权限边界和安全文本展示；替身测试不等于真实模型、
浏览器或官方 TCK 验收。本地 PGlite 也不能替代正式 PostgreSQL 并发锁测试。
