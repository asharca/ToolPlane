# A2A 资源准入与交付物限额

> [English](A2A_RESOURCE_LIMITS.md)

面向部署者和维护者。这是 ToolPlane 的资源策略，不是 A2A 新增字段或标准计费协议。
原生 A2A、MCP 适配和控制台使用同一任务核心，不能通过换入口重置任务或执行额度。

## 载荷与存储

每个 Task 快照仍最多 512 KiB；快照、请求、身份元数据、事件载荷和消息去重记录共同计入
`A2ATask.storageBytes`。JSON 使用数据库 UTF-8 序列化后的字节长度，去重记录按每条 512
单位计入。该数值是载荷计数，不等于包含索引、行头、WAL 和备份在内的实际磁盘占用。

活动或等待输入/授权的 Task 按至少 4 MiB 预留，终态按已保存载荷计入。正常写入上限留出
16 KiB 给失败/取消收尾，并限制事件序号不超过 128；失败终结允许写入必要的收尾事件。
如果成功结果超限，整笔结果事务回滚，不会留下已发布交付物但任务状态未提交的半成品。

工作区原生与兼容 Responses 请求共享准入锁和预算。工作区上限为十亿单位；公开服务还
检查 Endpoint 和 API 客户端的现有 `maxStoredCharacters` 设置。兼容记录保留原有字符
计数；原生任务保守地以载荷字节扣减同一上限。因此这是兼容的保守准入单位，不能解释为
精确可存字符数、磁盘字节数或账单。等待父任务释放执行槽，但仍占任务存储预留。

## 执行前输出预留

领取原生执行租约前，在同一事务中为工作区及适用的 Endpoint/客户端预留输出上界。
公开文本执行每轮预留 65,536 单位；本地执行另预留十五份 32 KiB 显式交付物，合计
557,056 单位。并发领取、重复消息或重复领取不能重复执行或绕过预算。

工作区每天最多五亿单位，公开调用同时受已有 Endpoint/客户端 `dailyOutputCharacterLimit`
约束。可能跨越 UTC 午夜的执行会同时预留两个日期，避免运行期间跨日越过限额。开始后
失败、取消或无输出都不自动退款，因为外部模型或工具是否已产生用量可能不确定。
这些数值不是实际 Token、实际输出用量或金额，不能据此向用户声称精确计费。

兼容 Responses 准入同样读取原生预留；原生准入也检查兼容请求的输出及存储占用。
数据写入都遵循工作区在前、Endpoint/任务在后的锁顺序。此能力仍要求单运行时所有者，
不代表已经支持分布式执行或 exactly-once 外部副作用。

## 错误与迁移

准入时超额使用实现自定义 JSON-RPC server error `-32099`，HTTP 入口返回 429 和有界
重试提示。这个数字不是新增的标准 A2A 语义错误。MCP 中表现为 `isError: true`。
已经接受但尚未运行的任务若在领取时无法预留额度，将失败终结，执行器不会启动。
已开始执行后的载荷超限不会撤销已经发生的外部副作用。

在前两份原生 A2A 迁移之后应用：

```text
20260923050000_a2a_storage_accounting
```

它仅新增并回填载荷计数字段和非负约束，不重放、删除或改写旧任务、身份、消息和交付物。
完成迁移后重新生成 Prisma Client。已保留的大任务按实际载荷计入，不会因新上限被静默删除。

验证包括持久化、回滚、重复领取、跨午夜、两种协议交叉额度及填充数据的迁移测试。
PGlite 明确跳过真正的 PostgreSQL 并发测试；生产前必须运行真实数据库与运行时验收。
